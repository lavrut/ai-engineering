## Concept

A tool returns data. Sometimes a person would rather see a small form than read JSON. An <Term t="MCP App" /> is a page of HTML that a server ships with a tool. A host that supports the Apps extension shows the page beside the tool call, in a sandboxed frame.

`lumen-ops` ships one App: a form to label a ticket. It shows the ticket and the proposed label, offers the six categories, and has two buttons, Confirm and Cancel.

### Three pieces

- **The resource.** The page is a resource at `ui://lumen/label.html` with the mime type `text/html;profile=mcp-app`. It is 7,051 bytes of HTML, CSS and script, with no build step.
- **The link.** `label_ticket` carries `_meta.ui.resourceUri = "ui://lumen/label.html"`. That is how a host knows the tool has a page.
- **The channel.** The page and the host talk JSON-RPC over `postMessage`, using the Apps extension's own methods: `ui/initialize`, `ui/notifications/tool-input`, `ui/notifications/tool-result` and `tools/call`. The page speaks version `2026-01-26` of the extension.

### The page cannot connect anywhere

The resource declares a Content Security Policy with every list empty: no connect domains, no resource domains, no frame domains, no base URI domains. The host applies it. So the page loads nothing from anywhere and cannot fetch anything. Its only way out is a message to the host.

### Confirm does not write

This is the point of the lesson. The Confirm button sends the host one request: `tools/call` on `label_ticket` with the chosen label. That call reaches `lumen-ops` like any other. It needs a `tickets:write` token, and the server asks its own confirmation question before it writes (lesson 8). The page says so: "The server will ask you to confirm again before it writes." A button in a page is never a way around the server.

<Callout kind="go" title="Python only">
  The App is Python only, by the track's design. Python's SDK, `mcp` 2.3.0, has the Apps extension built in (`mcp.server.apps.Apps`), so one call serves the page and links the tool. The Go SDK has no such helper, and a Go App would mean writing the same HTML a second time for no new idea. The Go `lumen-ops` is the same server without the page, and it answers the same contract.
</Callout>

## The code

Section 7 of `ops_server.py` builds the App.

<CodeTabs source="mcp-app" section={7} />

- `APP_URI = "ui://lumen/label.html"` is the resource's address. `APP_PATH` is the HTML file, `mcp/python/app/label.html`.
- `apps = Apps()` creates the SDK's Apps extension.
- `apps.add_html_resource(APP_URI, ..., csp=ResourceCsp(connect_domains=[], resource_domains=[], frame_domains=[], base_uri_domains=[]))` serves the page with the App mime type and the empty policy.

The link is made where the tool is registered, in section 4: `@apps.tool(resource_uri=APP_URI, annotations=WRITE)`. That puts `_meta.ui.resourceUri` on `label_ticket`, and keeps its write annotations. The server then takes the extension with `MCPServer(..., extensions=[apps])`.

Inside the page, the Confirm handler is a few lines:

- `request("tools/call", { name: TOOL, arguments: { id: ticketId, label: el.category.value } })` asks the host to call the tool. That is all Confirm does.
- `if (event.source !== window.parent) return;` ignores any message that does not come from the host.
- `say("wait", "Waiting for you to confirm in the host...")` tells the person that the question comes next, from the host.

## Try it

Run these from the repo root. Everything here is free and runs in memory.

### Find the App as a host does

Save this as `/tmp/try_app.py`, outside the repo, so nothing is left behind in it. It lists the tool, follows its link, and reads the page:

```python
"""Find the labelling App the way a host does: from the tool's _meta, then read it. Run it from the repo root."""
import asyncio
import sys
import tempfile
from pathlib import Path

sys.path.insert(0, "mcp/python")
from mcp import Client  # noqa: E402
from ops_server import build_ops_server  # noqa: E402


async def main() -> None:
    labels = Path(tempfile.mkdtemp()) / "labels.jsonl"
    async with Client(build_ops_server(labels_path=labels)) as client:
        [tool] = (await client.list_tools()).tools
        uri = tool.meta["ui"]["resourceUri"]
        print("tool:", tool.name, "-> App:", uri)
        [page] = (await client.read_resource(uri)).contents
        print("mime type:", page.mime_type)
        print("csp:", page.meta["ui"]["csp"])
        print("html:", len(page.text.encode()), "bytes; starts", page.text[:15])


asyncio.run(main())
```

```bash
.venv-mcp/bin/python /tmp/try_app.py
```

You should see `tool: label_ticket -> App: ui://lumen/label.html`, `mime type: text/html;profile=mcp-app`, the four empty CSP lists, and `html: 7051 bytes; starts <!doctype html>`.

### Render it in a reference host (optional, your choice)

The preview above is the course's own. If you want to see the page in the official reference host, the `modelcontextprotocol/ext-apps` repository on GitHub has one in `examples/basic-host`. It is not on npm, so you would clone the repository. Pin the tag `v2.0.3`, which matches the npm package we checked, and follow that example's README. We have not run it with `lumen-ops`. Keep two things in mind. It needs Node and the network. And `lumen-ops` only serves over HTTP with a `tickets:write` token, so the host must complete the OAuth flow from lesson 9 first. Never run `lumen-ops` without its token check to make a host work.
