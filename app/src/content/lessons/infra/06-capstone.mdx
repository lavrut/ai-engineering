## Concept

The capstone sends the whole course's recorded model traffic through the gateway and checks the result. It is the track's proof that the gateway does what the other five lessons say, on real traffic rather than fixture cases.

### The traffic

`infra/python/replay.py` replays all 957 calls the agents track recorded, in the order its runs made them. The four desk sets and the two patterns sets come from their runs' traces, each run's calls in order, repeats kept. The judge set has no traces, so its recordings go in file order. Each call carries `x-team`, as one of three teams, `desk`, `patterns` or `judge`, and `x-request-tag`, the ticket id its messages name, or `none`.

`--start` runs everything in one process: one agents replay proxy per set and one gateway, with fresh stores under `infra/data/derived/run/`. Before each call, the driver points the gateway at that call's set. Nothing is paid for and nothing is sent off the machine.

### Replay time

The gateway's limiter and its cache's time to live both read a clock. A replay from disk sends calls much faster than they were made, and lesson 1 showed what the wall clock does with that: the limiter sees a burst that never happened and refuses part of it.

So the capstone runs the gateway on replay time. The clock starts at 0 and, before each call, moves on by the previous call's recorded duration. A limiter wait moves it too, without sleeping. The gateway judges the pace the calls really had, and the replay itself still runs in seconds. Under the course's limits, that pace makes 0 retries and 0 refusals.

The other clock-bound number is latency. The p50 and p95 the capstone reports, 1730 ms and 3471 ms, come from each call's recorded duration, not from the replay. A trace's own `ms` is the gateway's time for the call, about nothing when the answer comes from a local file.

### The gate

`--gate` prints four lines, each `ok` or `FAILED`:

- **ledger:** for each desk set, the gateway's ledger plus the recorded cost of that set's cache hits equals the agents track's ledger, within 1e-9 of a dollar. Lesson 5 showed why the hits are added back.
- **budgets:** each team's spend is within its limit, and every refusal has a trace.
- **stages:** every trace has the stages in order: all eight for an answered call, five for a cache hit, and a refusal stops at the stage that refused. Every parent id a trace names exists in the run.
- **figures:** the hit rate counted from the traces and the p95 computed from the recordings equal the figures the capstone writes.

On the course's traffic all four pass. The stages line reads `957 traces: 937 answered with all eight stages, 20 cache hits stop after cache, 0 refusals stop at the refusing stage, 0 out of order; 0 parent ids named, 0 missing`.

### What the gate proves, and what it does not

The gate proves the gateway's own work. Its accounting matches the agents track's ledger to the cent, with every difference named. Its stages run in order. Its budgets held, and the figures it reports can be rebuilt from two independent sources.

It does not prove the desk did its job. A gateway sees calls, not tasks: it cannot tell a right triage from a wrong one, or a run that went round in circles from one that went straight to the answer. That is the agents track's scorer's job, over each run's trajectory. A gateway that answered every call proves nothing about what the desk did with the answers.

### The gap the caller must close

A trace can name its parent, the call it was made for, from the `x-parent-id` header. With parent ids, `traces.py --tree` shows one ticket's run as a tree: the supervisor's call, and under it its workers' calls.

The desk sends no parent id. Its supervisor and its four workers, triage, research, drafter and reviewer, each call the model, and nothing in those requests says which belong together. The gateway cannot work it out: a drop-in learns only what the request and its headers carry. The stages line says it plainly, `0 parent ids named`, and the Try it shows the flat tree that results.

## The code

The traffic is section 1 of `infra/python/replay.py`.

<CodeTabs source="infra-replay" section={1} pythonOnly />

- `def team_of(set_name: str) -> str:` maps the seven sets to three teams: every desk set is `desk`, both patterns sets are `patterns`.
- `entries = ([(c["key"], c["cost_usd"]) for c in trace_calls(root, s)] if s in TRACED_SETS else` takes a traced set's calls from its runs, in order, with what the agents ledger booked for each. The judge set falls back to its recordings.
- `m = TICKET_ID.search(messages_text(rs["body"]))` finds the ticket id the driver sends as the tag. A call whose messages name no ticket is tagged `none`.

The gate is section 3.

<CodeTabs source="infra-replay" section={3} pythonOnly />

- `saved = sum(r.call.cost_recorded or 0.0 for r in hits)` is what the set's cache hits cost when they were recorded, the money the gateway saved.
- `ok = abs(gw + saved - agents) <= 1e-9` is the ledger condition: the gateway's ledger plus the saving, against the agents ledger.
- `over = [t for t, v in spend.items() if t not in cap.cfg.budgets or v > cap.cfg.budgets[t].limit_usd]` finds any team over its limit, or spending with no budget at all.
- `expected = {"ok": list(STAGES), "cached": ["tag", "budget", "cache", "ledger", "trace"]}` is the order every answered call and every hit must show.
- `orphans = [p for p in parents if p not in ids]` checks every parent id names a trace in the run. With no parent ids, it has nothing to check.
- `ok4 = rate == figs["hit_rate"] and p95 == figs["p95_ms"]` compares the reported figures with the same figures rebuilt from the traces and the recordings.

<Callout kind="go" title="No Go twin here">
  The replay driver and the gate are Python only. The Go twin covers the request path, from the tag stage to the retry stage, and lessons 2 to 5 quote it. A team that ran the gateway in Go would run this same driver against it: the gate checks what a gateway did, not which language it is written in.
</Callout>

## Try it

Run the capstone. It replays all the calls, prints the gate and writes the three derived files the lessons read, with the same bytes as the committed ones:

```bash
.venv-infra/bin/python infra/python/replay.py --start --gate
```

You should see:

```text
replayed 957 calls: 20 cache hits, 0 refusals, $0.234425
gate ledger: ok: desk-hand $0.0457416 = agents $0.0457416; desk-hand-go $0.0458874 + $0.0001919 for 1 cache hit = agents $0.0460793; desk-langgraph $0.0442495 = agents $0.0442495; desk-sdk $0.0497478 = agents $0.0497478
gate budgets: ok: desk $0.1856 of $1.00, judge $0.0255 of $0.50, patterns $0.0233 of $0.50; 0 refusals, 0 traced
gate stages: ok: 957 traces: 937 answered with all eight stages, 20 cache hits stop after cache, 0 refusals stop at the refusing stage, 0 out of order; 0 parent ids named, 0 missing
gate figures: ok: hit rate 0.0209 (20 of 957) and p95 3471 ms; from the traces and the recordings: 0.0209 and 3471 ms
wrote capstone.json, ledger.json, traces.sample.json to infra/data/derived
```
