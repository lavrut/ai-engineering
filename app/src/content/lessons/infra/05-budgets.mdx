## Concept

A team with a budget wants two things from the gateway: to never go over it, and to know where the money went. The budget stage does the first, before each call. The ledger does the second, after it.

### The worst case, checked before the call

The budget stage runs second, right after the tag, before the cache, the route or the upstream. At that point the real cost is unknown: it depends on how many tokens the model will write. So the stage prices the worst case:

- **Input:** an estimate, about four characters a token over the request's JSON, at the model's input price.
- **Output:** every token `max_tokens` allows, at the model's output price.

It adds that to what the team has spent so far and compares the sum with the team's limit. The prices are the LLMs lab's table, so `claude-haiku-5-5` costs $0.10 a million input tokens and $0.50 a million output tokens. Every call in the patterns set asks for `max_tokens` of 4000, so its worst case is at least $0.002 before any input is counted.

The worst case is far above what a call usually costs. That is the point: the stage cannot know which call will run long, so it assumes each one might. The price is that a team is stopped early, with a little of its budget left that no call could safely use.

### Three answers, and the 402

The stage answers one of three ways:

- **allow:** the spend plus the worst case is within the limit.
- **warn:** it is within the limit but over the team's `warn_usd` line. The call goes on, and the trace says so, which is a team's early notice. In the fixture case `team_warn`, the desk has spent $0.85 against its warn line of $0.80, and the call is forwarded with a `warn`.
- **refuse:** it is over the limit, or the team has no budget at all. The gateway answers `402` with the reason in the body, and nothing is forwarded or spent. In `team_over_budget`, the desk has spent $0.9999 of its $1.00, and any call's worst case is too much.

A refusal comes before the cache, too. In `budget_refusal_beats_cache_hit`, the same over-spent desk asks for an answer the cache holds, and still gets the 402. A team over its budget is refused even what would have cost nothing, so the rule stays one rule.

Section 5 of `infra/gateway.yaml` sets the limits: the desk $1.00 with a warn line at $0.80, and the lab, patterns and judge teams $0.50 each. Its last line is `untagged: refuse`: a call with no `x-team` belongs to no team and is refused with a 402 too. A config can instead name a team to book untagged calls to, as lesson 1's Try it did.

### The ledger

Every call gets one ledger row, answered or refused: the team, the tag, the model, the four usage fields the API returns, the cost and the status. The rows are appended to a file and never rewritten. Each team's spend is the sum of its rows' costs, which is how the budget stage knows what a team has spent, even after a restart.

The cost comes from the recorded usage and the lab's prices. Prompt-cache tokens count at the API's multipliers: tokens written to the prompt cache at 1.25 times the input price, tokens read from it at 0.10 times. That is the agents proxy's own formula, in the same order, so the two ledgers price the same call the same way, to the last digit. A cache hit is booked at $0, because no model was called.

### The two ledgers beside each other

The agents track kept its own ledger: each run's traces list every proxy call and its cost. The capstone sends the same calls through the gateway and compares, per desk set. For three of the four desk sets the two figures are equal to the cent and beyond. The fourth, the Go hand-built desk, had 1 cache hit, which the gateway booked at $0 and the agents ledger still counts. So the gate adds back the recorded cost of each hit before it compares, and its line names the hits:

`desk-hand-go $0.0458874 + $0.0001919 for 1 cache hit = agents $0.0460793`

A hit is money the gateway saved, and the line shows how much. The patterns sets are not part of that check, but the same thing shows in their figures: `patterns-go` books less at the gateway than in the agents ledger, by its 19 hits.

Across the capstone, the desk spent $0.1856 of its $1.00, the judge $0.0255 of $0.50 and the patterns team $0.0233 of $0.50. No call was refused.

### Spend by ticket

The ledger keeps the tag beside the cost, so it can answer which tickets cost most. In the capstone, the dearest tag is `none`: calls whose messages name no ticket id, which the gateway cannot pin to a ticket. After it come `t001`, `t007` and `t061`, the three tickets the patterns sets run each pattern on, on top of the desk runs. A tag is only as good as what the caller sends. The capstone's driver tags each call with the ticket id it finds in the messages, and a call that names no ticket can only be booked to `none`.

## The code

The budget stage is section 3 of `infra/python/stages.py`.

<CodeTabs source="infra-stages" section={3} goSection={3} />

- `return len(canonical(body).decode()) // 4 + 1, out` estimates the input as a quarter of the JSON's characters, plus one, as the agents proxy estimates it. `out` is `max_tokens`, or 0 when the request sets none.
- `booked = cfg.untagged if team == "untagged" and cfg.untagged != "refuse" else team` books an untagged call to the team the config names, unless it says `refuse`.
- `priced = cfg.routes[model].to if model in cfg.routes else model` prices the call at its route's target, the model the ledger will book it under.
- `if spent + worst > b.limit_usd:` refuses on the worst case, before any token is spent. The warn line is checked only after it.
- `line = f"${spent:.6f} spent + ${worst:.6f} worst case"` is the detail every verdict carries, so the trace says how close the call came.

The chain turns a refusal into the 402 and puts the stage's detail in the body: `team {booked}: budget{lim} refused: {d['detail']}`.

The cost of an answered call is section 2 of `infra/python/ledger.py`.

<CodeTabs source="infra-ledger" section={2} pythonOnly />

- `if model not in prices or any(usage.get(k) is None for k in USAGE_FIELDS):` gives no cost rather than a wrong one when the usage is incomplete. The row says so with an empty cost.
- `+ usage["cache_read_input_tokens"] * CACHE_READ_MULTIPLIER * p_in` prices prompt-cache reads at a tenth of the input price. The write line above it uses 1.25.
- `return (in_tokens * p_in + out_tokens * p_out) / 1_000_000` is the worst case: no prompt-cache discount, the conservative side.

Section 4 rebuilds each team's spend from the rows.

<CodeTabs source="infra-ledger" section={4} pythonOnly />

- `if r.get("cost_usd") is not None:` skips refused calls and unpriced ones, so a refusal never counts against a team.

The limits are section 5 of the config.

<CodeTabs source="infra-config" section={5} pythonOnly />

- `desk: {limit_usd: 1.00, warn_usd: 0.80}` is the only team with a warn line.
- `untagged: refuse` refuses calls with no team. Replace `refuse` with a team's name to book them there.

## How Go does it

The Go twin's section 3 makes the same verdicts, and the twin test checks the same stage, verdict and status on every fixture case. The detail strings are written to match Python's, but the test does not compare them. Two lines show what that takes.

- `return utf8.RuneCountInString(Dumps(body, true))/4 + 1, out` counts characters, not bytes. Python's `len` counts code points, and a ticket with an accented name has more bytes than characters, so counting bytes would give Go a larger estimate.
- `d.LimitUSD = &lim` stores the limit as a pointer, so a team with no budget has no limit at all, as Python's `None`, rather than a limit of 0 that a reader could mistake for a real one.

## Try it

Start from an empty ledger, so the spend so far is nothing:

```bash
rm -f infra/data/ledger.jsonl infra/data/cache.json
```

In a first terminal, start the gateway on the course's config. No proxy is needed: every call below is refused before it would reach one.

```bash
.venv-infra/bin/python infra/python/gateway.py --port 8790 --run budget
```

You should see:

```text
gateway on http://127.0.0.1:8790 -> http://127.0.0.1:8791  traces infra/data/traces/budget.jsonl
```

In a second terminal, send the same request twice: once with no team, once as the patterns team. The request asks for up to 1,000,000 output tokens:

```bash
.venv-infra/bin/python -c "import http.client, json; body = json.dumps({'model': 'claude-haiku-5-5', 'max_tokens': 1000000, 'messages': [{'role': 'user', 'content': 'Triage ticket t008.'}]}); c = http.client.HTTPConnection('127.0.0.1', 8790); c.request('POST', '/v1/messages', body, {'content-type': 'application/json'}); r = c.getresponse(); print(r.status, r.read().decode()); c.request('POST', '/v1/messages', body, {'content-type': 'application/json', 'x-team': 'patterns'}); r = c.getresponse(); print(r.status, r.read().decode())"
```

You should see:

```text
402 {"type": "error", "error": {"type": "budget_exceeded", "message": "team untagged: budget refused: untagged requests are refused"}}
402 {"type": "error", "error": {"type": "budget_exceeded", "message": "team patterns: budget of $0.50 refused: $0.000000 spent + $0.500003 worst case > $0.50 limit"}}
```

The first has no team. The second has a team with nothing spent, but its worst case alone is more than the team's whole budget. Neither reached an upstream, and both are traced:

```bash
.venv-infra/bin/python infra/python/traces.py infra/data/traces/budget.jsonl
```

You should see:

```text

487edccafbf4e65d 402 patterns t008 0 - refused
```

Your trace ids and the gateway's own milliseconds, the fifth field, will differ. The cost is `-`: a refusal is booked with no cost. Stop the gateway with Ctrl-C.
