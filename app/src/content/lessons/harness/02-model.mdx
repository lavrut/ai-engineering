## Concept

You talk to Claude through an HTTP API. Every request is authenticated with an <Term t="API key" />, which you create in the Anthropic Console and keep out of your code. The SDK reads it from the `ANTHROPIC_API_KEY` environment variable, and the harness reads it from nowhere else. Set it without typing the key into a command line, where your shell history would keep it:

```bash
read -rs ANTHROPIC_API_KEY && export ANTHROPIC_API_KEY
```

Paste the key and press Enter. Nothing is echoed, and the variable lasts until you close that terminal. The harness never prints or logs the key.

A request is a JSON body. The conversation goes in <Term t="messages" />, a list of turns. Each turn has a <Term t="role" /> and some content. The `user` role is anything your side sends; the `assistant` role is anything the model wrote. In this harness the turns alternate, starting with `user`.

The model remembers nothing between calls. To continue a conversation, you send the whole list again with the new turn on the end. Standing instructions go in a separate `system` field: the <Term t="system prompt" />.

The model reads and writes in <Term t="token">tokens</Term>, pieces of text a little shorter than a word. Limits and prices are counted in them. You cap the reply with <Term t="max_tokens" />. Opus 5.5 costs $4 per million input tokens and $20 per million output tokens, and you pay for the whole history on every call.

The response holds a list of <Term t="content block">content blocks</Term>. A block is text or a `tool_use` request. Next to the content sit two fields you will check on every reply: `stop_reason`, which says why the model stopped, and <Term t="usage" />, which counts `input_tokens` and `output_tokens`.

| `stop_reason` | Meaning |
|---|---|
| `end_turn` | The model finished its reply. |
| `tool_use` | The model wants the harness to run one or more tools. |
| `max_tokens` | The reply hit your `max_tokens` cap and was cut off. |
| `refusal` | The model declined the request. |

## The code

Section 1 sets the constants every call uses.

<CodeTabs section={1} goNote="Go keeps the same values as const and var. The client is built with anthropic.NewClient(option.WithMaxRetries(4)), which reads ANTHROPIC_API_KEY just like the Python SDK. maxTurns is a var instead of a const so the tests can lower it." />

- `MODEL = "claude-opus-5-5"` names the model on every request.
- `MAX_TOKENS = 16_000` is the default cap on one reply.
- `SYSTEM_PROMPT` is the standing instruction. It tells the model where it is working and how to behave.
- `PRICE_PER_MTOK = (4.00, 20.00)` is the model's price in dollars per million input and output tokens, the same figures as the LLMs track's price table. `MAX_COST = 10.00` is the default cap on what one REPL session may spend. The money gate in section 9 uses both, with `TYPICAL_TASK` and `CHARS_PER_TOKEN` for its estimates (lesson 8).
- `client = anthropic.Anthropic(max_retries=4)` creates the API client. It reads the key from the environment and retries rate limits (HTTP 429), server errors and network failures up to four times.

Section 6 makes the call itself. This is steps 2 to 4 of the flow: build the request, send it, get the reply.

<CodeTabs section={6} goNote="callModel takes the params struct the caller built with Messages and fills in Model, System, Tools and MaxTokens, then calls client.Messages.New(ctx, params, opts...). System is a list of text blocks. MaxTokens is set only when the caller left it at zero, so compaction can ask for a shorter reply. Failures come back as an error value instead of an exception. textOf, also in this section, joins the text blocks of a reply; Python does the same with a one-line join in the loop." />

- `params` holds the request: `model`, `max_tokens`, `system`, `tools` (lesson 3) and `messages`.
- The `USE_FALLBACKS` lines add a beta header and a `fallbacks` field. If a safety classifier declines the request, the API retries it on a fallback model. You can leave this as it is.
- `params.update(overrides)` lets a caller change one field for a single call. Compaction in lesson 7 uses it.
- `client.messages.create(**params)` sends the request and waits for the reply.
- The two `emit` calls write the number of messages in the request, then the response's `stop_reason` and token counts to the trace.
- `call_model` returns the whole response. The loop in lesson 4 reads `response.content` and `response.stop_reason` from it.

<Callout kind="note" title="Where the history lives">
  `call_model` does not keep any state. The caller passes in `messages`, and the agent loop owns that list. This keeps the model call easy to test and easy to swap for a fake.
</Callout>

## Try it

Make one call without the harness, so you can see the raw response. This call costs money, but very little: at most 200 output tokens, which is $0.004 at $20 per million, plus a few dozen input tokens. Save this as `harness/python/one_call.py`:

```python
import anthropic

client = anthropic.Anthropic()
response = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=200,
    system="Answer in one sentence.",
    messages=[{"role": "user", "content": "What is a token?"}],
)
for block in response.content:
    print(block.type, "->", block.text)
print("stop_reason:", response.stop_reason)
print("usage:", response.usage.input_tokens, "in,", response.usage.output_tokens, "out")
```

Run it with the virtual environment you made in lesson 1:

```bash
cd harness/python
../../.venv-harness/bin/python one_call.py
```

You should see one `text` block, `stop_reason: end_turn`, and two small token counts. Now set `max_tokens=5` and run it again: the sentence is cut short and `stop_reason` is `max_tokens`.

Then run the harness once more (a paid task: it prints the estimate and asks first, as in lesson 1) and look at what it logged for each call:

```bash
../../.venv-harness/bin/python harness.py
grep model_response trace.jsonl
```

Each line shows the `stop_reason` and token counts for one model call. Notice that `input_tokens` grows on each call in a session, because the full history is sent every time.
