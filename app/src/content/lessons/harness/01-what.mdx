## Concept

A language model is a function behind an API. You send it text, it sends text back. It cannot open files, run commands, or remember your last request. Everything that makes it act like an agent lives in ordinary code that you write.

That code is the <Term t="harness" />. It takes your task, builds a request, sends it to the model, reads the reply, runs any tools the model asked for, and sends the results back. It repeats until the model says it is done.

The model's reply can only take two forms: text for you, or a request to call a tool. A request to call a tool is a <Term t="tool_use" /> block: a tool name plus JSON input. The model never runs code. The harness does, and reports back with a <Term t="tool_result" />.

The harness in this course has a handful of parts, each a short function:

- **Entry point.** A small loop that reads your task from the terminal.
- **Context builder.** Assembles each request from the <Term t="system prompt" />, the conversation so far, and the tool descriptions.
- **Router.** Reads the reply's <Term t="stop_reason" /> and picks the next step.
- **Permission gate.** Asks you before a risky tool runs, such as a file write.
- **Tool executor.** Runs the approved tools and collects their output.
- **Context manager.** Watches the size of the conversation and shrinks it when it grows too large.
- **Trace log.** Writes every step to a file so you can see what happened.

## The code

The harness is two files that do the same thing: `harness/python/harness.py` and `harness/go/main.go`. Each is split into nine numbered sections with the same titles, so you can read them side by side. Later lessons show these sections one at a time.

| Section | What it holds | Flow step |
|---|---|---|
| 1. Configuration | Model id, limits, system prompt, API client | |
| 2. Observability | `emit`, which writes `trace.jsonl` | every step |
| 3. Tool registry | Tool definitions and the sandbox rule | |
| 4. Permission gate | `approve` | 6 |
| 5. Tool executor | `run_one`, `execute_tools` | 7 |
| 6. Model call | `call_model` | 2 to 4 |
| 7. Context management | `compact` | 9 |
| 8. The agent loop | `run_agent` | 5, 8 |
| 9. Entry point | `main`, the REPL | 1, 10 |

<Callout kind="note" title="Why two languages">
  Python is the easiest to read. Go shows the same design with explicit types, goroutines and a per-tool deadline (which only tools that watch their context obey). Pick one to run; the lessons point out where the Go version differs.
</Callout>

## Try it

This step calls the API, so it costs money. The harness prints an estimate and asks before it spends anything. You need an Anthropic API key; lesson 2 shows how to set it without typing it into your shell history. Set up the Python harness once, from the repo root, in its own virtual environment, then start it:

```bash
python3 -m venv .venv-harness && .venv-harness/bin/pip install -r harness/python/requirements.txt
cd harness/python
mkdir -p workspace && echo "Buy milk. Call Sam." > workspace/notes.txt
../../.venv-harness/bin/python harness.py
```

At the `you >` prompt, type `What files are in the workspace, and what does notes.txt say?` Before the first model call, the harness prints its estimate for the task and asks:

```text
Estimate: typical $0.10 a task (4 calls of ~4,000 input and ~400 output tokens); worst case $23.00 (MAX_TURNS 25 calls of 150,000 input and 16,000 output tokens, plus any compaction summaries), at $4.00 / $20.00 per million tokens.
Spent $0.0000 this session; --max-cost stops it before $10.00.
Run it? [y/N]
```

This is the harness's money gate. The typical figure assumes a short task like this one. The worst case is a task that uses all 25 turns with the full 150,000-token history and a full 16,000-token reply each time. Type `y` to run the task. Anything else skips it and spends nothing, and so does running the harness without a terminal to ask. While the task runs, the harness checks before every model call that what the session has spent, plus the most that call could cost, stays under `--max-cost`. That cap is $10 unless you start the harness with a lower one, such as `../../.venv-harness/bin/python harness.py --max-cost 1`. If the next call could pass it, the task stops before the call is made. After each task the harness prints what the task cost and what the session has spent so far.

You should see lines such as `-> list_files({"path": "."})` and `-> read_file({"path": "notes.txt"})` as the harness runs each tool, then `agent >` with a short answer. Type `exit` to quit. A new `trace.jsonl` file in the same folder holds one line per event; you will read it in lesson 8.

To run the Go version instead: `cd harness/go && go run .` (the workspace folder is `harness/go/workspace`). It prints the same estimate and asks the same way.
