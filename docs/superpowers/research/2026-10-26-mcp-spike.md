## Step 1: local authorization server in Python (works)

**SDK facts (read in source):**
- `mcp/server/auth/provider.py`:
  - `OAuthAuthorizationServerProvider` protocol: `get_client`, `register_client`, `authorize`, `load_authorization_code`, `exchange_authorization_code`, refresh, `load_access_token`, `revoke_token`.
  - `AuthorizationParams.resource` and `AuthorizationCode.resource` carry RFC 8707.
  - `TokenVerifier.verify_token(token) -> AccessToken | None`; `AccessToken.resource` is what the bearer middleware compares.
  - `construct_redirect_uri` helper.
- `mcp/server/auth/routes.py`:
  - `create_auth_routes(provider, issuer_url, ..., client_registration_options=...)` serves `/.well-known/oauth-authorization-server`, `/authorize`, `/token` and (when enabled) `/register`.
  - `validate_issuer_url` allows `http` only for `localhost`, `127.0.0.1` and `[::1]`.
  - `build_metadata` never sets `client_id_metadata_document_supported`.
- `mcp/server/auth/settings.py`: `AuthSettings(issuer_url, resource_server_url, required_scopes, validate_token_resource)`. Leaving `validate_token_resource` unset warns and behaves as False.
- `mcp/server/auth/middleware/bearer_auth.py`:
  - `BearerAuthBackend` rejects a token unless `AccessToken.resource` equals `resource_server_url` (URL-normalised, trailing slash ignored). The request then has no user, so the response is 401.
  - `RequireAuthMiddleware` returns 401 `invalid_token` or 403 `insufficient_scope`, with `WWW-Authenticate: Bearer error=..., error_description=..., resource_metadata="..."`.
- `mcp/server/mcpserver/server.py`:
  - `MCPServer(auth=..., token_verifier=...)` or `auth_server_provider=...` (not both).
  - It serves PRM at `/.well-known/oauth-protected-resource/mcp` (`create_protected_resource_routes`) with `authorization_servers=[issuer_url]` and `scopes_supported=required_scopes`.
- `mcp/server/auth/handlers/token.py`:
  - The token endpoint checks PKCE S256 and that `redirect_uri` is unchanged. It does **not** compare the token request's `resource` with the code's `resource`, and the provider never sees the token request's `resource`.
  - So the AS must bind `aud` to the `resource` given at `/authorize` (`AuthorizationCode.resource`).

**Architecture:** the AS is separate from the resource server. It is a Starlette app on `127.0.0.1:9000` built from the SDK's routes. The SDK also lets `MCPServer(auth_server_provider=...)` co-host the AS, but separation is what the spec models and what the Go RS needs.

**The resource server** (`ops_rs.py`):

```python
class JWTVerifier:
    async def verify_token(self, token: str) -> AccessToken | None:
        try:
            c = jwt.decode(token, SECRET, algorithms=["HS256"], issuer=ISSUER,
                           options={"verify_aud": False, "require": ["exp", "iss", "aud"]})
        except jwt.PyJWTError:
            return None
        return AccessToken(token=token, client_id=c["client_id"], scopes=c.get("scope", "").split(),
                           expires_at=c["exp"], resource=c["aud"], subject=c.get("sub"), claims={"iss": c["iss"]})

mcp = MCPServer("lumen-ops-spike", token_verifier=JWTVerifier(), auth=AuthSettings(
    issuer_url="http://127.0.0.1:9000", resource_server_url="http://127.0.0.1:8766/mcp",
    required_scopes=["tickets:write"], validate_token_resource=True))
uvicorn.run(mcp.streamable_http_app(host="127.0.0.1"), host="127.0.0.1", port=8766)

```

`verify_aud=False` is deliberate. The verifier reports `aud` as `AccessToken.resource`, and the SDK's `validate_token_resource=True` enforces it. Do not check `aud` in both places, because a duplicate check hides which layer did the work.

**Client registration:**
- **Pre-registered: works.** It is shown above. The client skips registration when `TokenStorage.get_client_info()` returns the client.
- **DCR: works.** With empty storage, the client POSTed `/register` and got a UUID `client_id`. The rest of the flow was identical (`whoami: client=d9123793-...`). Registration needs `ClientRegistrationOptions(enabled=True, ...)`. DCR is deprecated in 2026-07-28.
- **CIMD: not supported out of the box.**
  - Evidence 1: `build_metadata` never advertises `client_id_metadata_document_supported`. So `OAuthClientProvider(..., client_metadata_url="https://lumen.example/oauth/client.json")` silently **fell back to DCR** in the run (`client_id used: 79e88231-...`). Source: `mcp/client/auth/utils.py:should_use_client_metadata_url`.
  - Evidence 2: the SDK client rejects non-HTTPS CIMD URLs: `ValueError: client_metadata_url must be a valid HTTPS URL with a non-root pathname, got: http://127.0.0.1:9100/client.json` (`is_valid_client_metadata_url`). A local, http-only course setup therefore cannot host a real client document.
  - Evidence 3 (`cimd_probe.py`): the SDK's AS pipeline *can* carry a URL client id if we add CIMD ourselves. We prepended our own `/.well-known/oauth-authorization-server` route with `client_id_metadata_document_supported: true`, and wrote a `get_client` that resolves `https://` client ids. The document fetch was a **stub dict**, because no local HTTPS host exists. With that, the full flow worked: `client_id used: https://lumen.example/oauth/client.json`, 200 with the flow token, and 401/403 as above. This was not a real CIMD fetch.
- **Ruling:**
  - `auth_server.py` uses a **pre-registered public client** `lumen-cli`, with redirect `http://127.0.0.1:33418/callback`, `token_endpoint_auth_method="none"` and PKCE.
  - DCR stays enabled.
  - Lesson 9 explains that CIMD is preferred, and that it needs an HTTPS client document that our loopback-only lab cannot serve.
  - Auth is never dropped.

**`http://127.0.0.1` resource URIs:**
- **Accepted**: the AS issuer, the PRM `resource`, the `resource` parameter and the token `aud` all used `http://127.0.0.1:...` with no errors or warnings.
- Redirect URIs are matched exactly, including the port, so use a fixed callback port (`OAuthClientInformationFull.validate_redirect_uri`).

**Other observations:**
- RFC 9207 `iss` is validated by the client. A wrong `iss` in the redirect failed with `OAuthFlowError: Authorization response iss mismatch` (seen during the probe), so the AS must stamp its own issuer.
- Python's 401/403 `WWW-Authenticate` has no `scope="..."` parameter. Go's does.

## Step 2: Go resource server (works)

**SDK facts (read in source):**
- `auth/auth.go`:
  - `RequireBearerToken(verifier, &RequireBearerTokenOptions{ResourceMetadataURL, Scopes})`.
  - A verifier error that wraps `auth.ErrInvalidToken` gives 401. A missing scope gives 403 `insufficient scope`. A zero `Expiration` gives 401 unless `AllowMissingExpiration`.
  - **There is no audience check in the middleware.**
  - `WWW-Authenticate: Bearer resource_metadata="...", scope="..."` goes on both 401 and 403. It has no `error=` parameter.
  - `ProtectedResourceMetadataHandler(&oauthex.ProtectedResourceMetadata{...})` serves the PRM.
- `oauthex/audience.go`: `MatchesResource(claims, resource)` compares exactly, except that a trailing slash is ignored.
- `mcp/shared.go`: tools read the token via `req.Extra.TokenInfo`.

The token is an HS256 JWT verified with the standard library. go-sdk v1.8.0 has no JWT dependency, and the course adds none.

```go
func verifyJWT(_ context.Context, token string, _ *http.Request) (*auth.TokenInfo, error) {
	parts := strings.Split(token, ".")
	if len(parts) != 3 { return nil, auth.ErrInvalidToken }
	// header alg must be HS256; HMAC-SHA256 over parts[0]+"."+parts[1] with the shared test key; hmac.Equal
	...
	if json.Unmarshal(b, &c) != nil || c.Iss != issuer { return nil, auth.ErrInvalidToken }
	if !oauthex.MatchesResource([]string{c.Aud}, resource) {          // audience -> 401
		return nil, fmt.Errorf("%w: audience %q", auth.ErrInvalidToken, c.Aud)
	}
	return &auth.TokenInfo{Scopes: strings.Fields(c.Scope), Expiration: time.Unix(c.Exp, 0),
		UserID: c.Sub, Extra: map[string]any{"client_id": c.ClientID}}, nil
}

mcpHandler := mcp.NewStreamableHTTPHandler(func(*http.Request) *mcp.Server { return server },
	&mcp.StreamableHTTPOptions{Stateless: true})
protect := auth.RequireBearerToken(verifyJWT, &auth.RequireBearerTokenOptions{
	ResourceMetadataURL: "http://127.0.0.1:8767/.well-known/oauth-protected-resource/mcp",
	Scopes:              []string{"tickets:write"},                    // scope -> 403
})
mux := http.NewServeMux()
mux.Handle("/.well-known/oauth-protected-resource/mcp", auth.ProtectedResourceMetadataHandler(
	&oauthex.ProtectedResourceMetadata{Resource: resource, AuthorizationServers: []string{issuer},
		ScopesSupported: []string{"tickets:write"}, BearerMethodsSupported: []string{"header"}}))
mux.Handle("/mcp", protect(mcpHandler))
http.ListenAndServe("127.0.0.1:8767", mux)
```

**Notes for Task 8:**
- The Go middleware checks scopes *before* expiry. The verifier should therefore reject expired tokens itself if expired tokens must give 401 rather than 403.
- The shared HS256 key means any holder of the key could mint tokens. That is acceptable only for a loopback test AS. RS256 with a JWKS is the production shape; say so in the lesson.

## Step 4: elicitation round trip (works in Python and Go)

### Python: the `Resolve` + `Elicit` resolver (MRTR)

**SDK facts:**
- `mcp/server/mcpserver/resolve.py`:
  - `Annotated[T, Resolve(fn)]` fills a parameter by running resolver `fn` (which may take tool arguments by name) before the tool body.
  - A resolver returning `Elicit(message, Model)` becomes an `elicitation/create` entry in an `InputRequiredResult` on 2026-07-28. On ≤ 2025-11-25 it becomes a standalone server-to-client request.
  - Annotating the consumer `ElicitationResult[T]` gives accept, decline and cancel to the tool body. A bare `T` aborts the call on decline or cancel.
  - The tool body runs only on the final round, so the write happens once.
- `mcp/server/elicitation.py`: `AcceptedElicitation(data=...)`, `DeclinedElicitation`, `CancelledElicitation`.
- `Context.elicit(...)` (push-style, `mcp/server/mcpserver/context.py`) was **not tested**. The resolver was verified on both eras (see the legacy table below), so use the resolver.

```python
class Confirm(BaseModel):
    confirm: bool

def ask_confirm(id: str, label: str) -> Elicit[Confirm]:
    if label not in LABELS:                      # validate BEFORE asking: never confirm an invalid write
        raise ToolError("label must be one of: " + ", ".join(LABELS))
    return Elicit(f"Write label '{label}' on ticket {id}?", Confirm)

@mcp.tool()
def label_ticket(id: str, label: str,
                 answer: Annotated[ElicitationResult[Confirm], Resolve(ask_confirm)]) -> CallToolResult:
    if answer.action != "accept" or not answer.data.confirm:
        return CallToolResult(content=[TextContent(type="text", text="label not written: the user declined")],
                              is_error=True)
    ...write row with confirmed=True...
```

**Client:** `Client(..., elicitation_callback=cb)`, where `async def cb(context, params) -> ElicitResult`. Import `ElicitResult` from `mcp_types`. `params.message` and `params.requested_schema` are available. The `Client` drives the retry rounds automatically, up to `input_required_max_rounds`.

```python
async def cb(context, params):
    return ElicitResult(action="accept", content={"confirm": True})   # or ElicitResult(action="decline")
```

The raw first round came from `await c.session.call_tool(name, args, allow_input_required=True)`. The input-request key is the resolver's qualified name.

**Important findings for Task 7:**
- **`raise ToolError(msg)` prefixes the text**: `'Error executing tool label_ticket: label not written: the user declined'`. To keep the fixed messages identical to Go, return `CallToolResult(is_error=True, content=[TextContent(...)])`. This was verified: `decline: True 'label not written: the user declined'`.
- A client **without** an elicitation callback gets JSON-RPC error `-32021` (`Client did not declare the form elicitation capability required by resolver ...`, with `data={'requiredCapabilities': {'elicitation': {'form': {}}}}`). Nothing is written, so it fails closed.
- The `request_state` is sealed by `RequestStateSecurity.ephemeral()` by default. The key is per process, so a server restart between rounds makes the client re-ask. That is fine for the lab.

### Go: `InputRequiredResult` by hand

**SDK facts:**
- `mcp/protocol.go`:
  - `CallToolResult.InputRequests` (`InputRequestMap`, values like `*mcp.ElicitParams`) and `CallToolResult.RequestState`.
  - The retry arrives as `req.Params.InputResponses` (`InputResponseMap`, values `*mcp.ElicitResult`) and `req.Params.RequestState`.
  - The doc comment says unauthenticated servers must encrypt, sign and verify `RequestState`.
- `mcp/mrtr.go`:
  - The server sets `resultType: input_required` for 2026-07-28 clients.
  - For older clients it fulfils the requests itself with server-to-client calls and re-invokes the handler.
  - The client middleware fulfils requests automatically through `ClientOptions.ElicitationHandler`, up to 10 rounds.
- There is no `Elicit`-style helper.

```go
func labelTicket(ctx context.Context, req *mcp.CallToolRequest, in LabelIn) (*mcp.CallToolResult, any, error) {
	resp, ok := req.Params.InputResponses["confirm"]
	if !ok { // round 1: ask
		return &mcp.CallToolResult{
			InputRequests: mcp.InputRequestMap{"confirm": &mcp.ElicitParams{Mode: "form",
				Message: fmt.Sprintf("Write label '%s' on ticket %s?", in.Label, in.ID),
				RequestedSchema: map[string]any{"type": "object",
					"properties": map[string]any{"confirm": map[string]any{"type": "boolean"}},
					"required":   []string{"confirm"}}}},
			RequestState: sign(in), // HMAC over id+label: binds the answer to these exact arguments
		}, nil, nil
	}
	if !hmac.Equal([]byte(req.Params.RequestState), []byte(sign(in))) {
		return text("label not written: the user declined", true), nil, nil // fail closed
	}
	er, _ := resp.(*mcp.ElicitResult)
	if er == nil || er.Action != "accept" || er.Content["confirm"] != true {
		return text("label not written: the user declined", true), nil, nil
	}
	... write ...
}
```

## Other verified facts

- **Origin (Python):**
  - `streamable_http_app(host="127.0.0.1")` enables DNS-rebinding protection automatically. It allows hosts `127.0.0.1:*`, `localhost:*` and `[::1]:*`, and origins `http://127.0.0.1:*` and friends (`mcp/server/lowlevel/server.py` around line 753).
  - `Origin: http://evil.example` gives **403**, and `Origin: http://127.0.0.1:6274` gives 200 (both with a valid token).
  - Without a token, a bad Origin gets **401**, because auth runs before the Origin check.
- **The SDK's HTTP client is `httpx2`**, not `httpx`.
  - Build an authenticated client with `create_mcp_http_client(headers=..., auth=...)` from `mcp.shared._httpx_utils` (a private module path, but the one the SDK uses).
  - Pass it with `streamable_http_client(url, http_client=...)` from `mcp.client.streamable_http`.
  - The result goes to `Client(...)` as a transport.
