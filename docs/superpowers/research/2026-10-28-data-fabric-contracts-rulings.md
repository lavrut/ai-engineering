# Data Fabric & Data Contracts track: rulings made during the build

Date: 2026-10-28. Branch `feat/data-track`. Spec `docs/superpowers/specs/2026-10-28-data-fabric-contracts-design.md`, plan `docs/superpowers/plans/2026-10-28-data-fabric-contracts.md`. Each is `what — why — cost if wrong`, from the build ledger in the order made.

- D1: Task 1's `contract.py` also provides `--export <contract.yaml>` writing `<same path>.contract.json` (the machine form, keys sorted, trailing newline) and `--export --check` over `data/contracts/*.yaml`; Go reads the JSON; the YAML is the source — cost if wrong: none
- D2: Task 4's lineage edges carry `"version"` (from the contract's consumer entry) from the start, so Task 5 adds no shape change — cost if wrong: none
- D3: `read_rows` accepts three forms: JSONL (one object per line), a JSON array, or a single top-level JSON object (one row); documented in the contract module and covered by a fixture case — cost if wrong: none
- D4: contract `pattern` values are anchored by the contract author and restricted to the syntax Python `re` and Go RE2 share (no lookarounds, backreferences or possessive quantifiers); `load_contract` rejects a pattern using them with a `ContractError`; a fixture case covers an anchored pattern — cost if wrong: a pattern that Python accepts and Go rejects shows as a twin mismatch, which the twin test catches
- D5: the export file name strips `.yaml`: `tickets.v1.yaml` → `tickets.v1.contract.json` (Task 2 globs `*.contract.json`) — cost if wrong: none
- D6 (widens D4): Python compiles contract patterns with `re.ASCII` so \d \w \s \b mean what RE2 means; `load_contract` also rejects inline flags `(?i)`/`(?x)`/`(?s)`/`(?m)` and the `{,n}` quantifier; the detail for an invalid pattern is the fixed text "invalid pattern" (no engine error text) in both languages; a contract-file load failure reads "not a valid contract file" in both — cost if wrong: a Unicode-digit edge case nobody has
- D7 (supersedes the deny-lists of D4/D6): contract patterns use an ALLOW-LIST grammar checked by the same small tokenizer in both languages before compiling: literals; `.`; escaped metacharacters `\. \* \+ \? \( \) \[ \] \{ \} \| \^ \$ \\ \-`; the classes `\d \D \w \W \s \S` which both languages rewrite to explicit ASCII classes (`[0-9]`, `[A-Za-z0-9_]`, `[ \t\n\r\f]` and their negations) before compiling; bracket classes `[...]`/`[^...]` with literal characters, ranges and the six class escapes; groups `(...)` and `(?:...)`; alternation `|`; quantifiers `* + ? {n} {n,} {n,m}` (no `{,n}`, no possessives, no lazy `?` suffix); anchors `^` and `$` only at the pattern's start and end (they are redundant under full match). Anything else → `ContractError` / load failure with the fixed detail "invalid pattern: <offending token>" in both languages; a contract-file load failure reads "not a valid contract file" in both. The grammar is stated in `data/fixtures/README.md` and lesson 5 — cost if wrong: a contract author loses regex features nobody's dataset needs
- D8: `unique` takes a list of field names and means the tuple is unique across rows (a composite key); a missing key field in a row is a `unique` failure naming the row, not a crash; the fixture file already covers it per the Task 2 review — cost if wrong: none
- D9: the pattern grammar caps counted repeats at 1000 (`{n}`, `{n,}`, `{n,m}` with n, m ≤ 1000) and forbids a counted repeat applied to a group that itself contains a counted repeat; both tokenizers reject them with `invalid pattern: <token>`; folded into Task 3's dispatch as a small side item with a fixture case — cost if wrong: none
- D10: freshness is computed as of a pinned date: `verdicts.json` stores `as_of` (the date it was generated) and every `age_days` relative to it; `--check` recomputes with the stored `as_of`, so it stays stable; `quality.py --live` (and the lesson 3 Try-it) uses today's date and will fail once a dataset passes `max_age_days`, which is the teaching point and is stated in lesson 3; tests use a fixed `as_of` — cost if wrong: none
- D11: the agents consumer test may stub, in sys.modules, only modules the ticket loader never calls (the MCP agent bridge), with a comment saying why; it must still import the real `desk_core` and call the real `load_eval_tickets` — cost if wrong: none
- D12: `gate.py` re-validates each consumer's declared contract against the dataset it governs (using the pinned `as_of`), never trusting verdicts.json; per consumer it reports `sunset` and sets `warning` when the declared version is deprecated and the pinned date is past its sunset (a warning, not a failure, before the sunset); lesson 6 shows the v1 consumer with its sunset — cost if wrong: none
- D13: the migrated file is a dataset of its own in the catalogue: id `tickets_v2`, path `data/data/tickets.v2.jsonl`, producer `data`, contract `tickets.v2`, consumer `agents-eval`; lineage then shows the two files and the two versions — cost if wrong: none
- D14: `data-contract`'s Go files are ordered `contract.go`, `rules.go`, `main.go` so a whole quote reads sections in order; `data-migrate` stays a separate source (overlapping section numbers) — cost if wrong: none
- D15: lesson 1 states the mapping honestly: the course's five sections are "in the shape of" ODCS, naming the ODCS sections each corresponds to (fundamentals/info, schema, quality, servicing/SLA, team/roles+consumers) and saying the names are the course's own — cost if wrong: one paragraph
- D16 (final review I1): both validators cap nesting at 64 levels and refuse a lone surrogate escape BEFORE decoding, with one lexical pass that is the same in both languages (`_scan` / `scan`); each is a `parse` problem with identical text, `row N: nesting deeper than 64` and `row N: invalid unicode escape`, where N is the JSONL line or the array item; Python also catches `RecursionError`, so CPython's C stack never decides a verdict and printing never meets a surrogate; Go detects the escape itself because its decoder substitutes U+FFFD; fixture cases and twin edges cover both — cost if wrong: a dataset nesting deeper than 64 is refused, which no course dataset does
- D17 (final review I2): without full git history (a shallow clone, CI's default checkout, or a zip / `git archive` copy) `quality.has_history` is false, so `commit_time` and `catalog.last_commit` return None; `catalog.py --check` and `quality.py --check` then compare everything except the git-derived fields (`last_commit`, `age_days`, the freshness detail) and print `no git history: commit dates not compared`; the tests that measure real commit dates skip with `needs full git history: run git fetch --unshallow` (probed once per session in `data/python/tests/history.py`); `test_lesson_tryits.py` snapshots the watched files before each command and puts back any it changed, so no committed file is ever left changed — cost if wrong: a CI job without `fetch-depth: 0` checks everything but the dates
- D18 (final review I3): `last_commit` stores the full 40-character sha (`git log -1 --format=%H`), because git's own abbreviation grows with the repo; the catalogue explorer shows the first 7 characters — cost if wrong: none
- D19 (final review I4; amends D13): the agents track's own loader (`agents/desk/python/desk_core.py`) still reads the v1 file, so it stays a declared consumer: `tickets.v1` consumers are `mcp-read-server` v1 and `agents-eval` v1; `tickets.v2`'s consumer is `agents-eval-v2`, the stand-in shim `data/python/consumers/agents_eval_v2.py`, which shows what the agents eval's migration looks like. The consumer tests, catalogue (tickets read by agents and mcp), lineage (32 edges, `tickets -> agents-eval` and `tickets_v2 -> agents-eval-v2`), gate (5 of 5, both agents consumers green on their declared versions), the `data-fabric` diagram, lessons 1, 2, 4 and 6 and the v1 contract header tell that story: the agents track has not migrated yet; `tickets.v1` can be retired only after both it and the MCP read server move — cost if wrong: none
